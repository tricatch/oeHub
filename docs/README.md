# oeHub 설계 문서

이 디렉터리는 oeHub를 평가, 배포, 또는 기여하려는 모든 사람을 위해 시스템의 아키텍처와 설계 결정을
문서화합니다. 최상위 `README.md`(설치와 일상적인 사용법을 다룸)를 보완하여, 번들된 두 도구가 어떻게
맞물리는지, 멀티테넌트 배포가 어떻게 동작하는지, 종단간 암호화가 어떻게 설계되었고 그 보장 범위가
어디서 끝나는지 — 즉 시스템의 *이유*를 다룹니다.

순서대로 읽거나, 필요한 부분으로 바로 이동하세요.

1. **[개요](01-overview.md)** — oeHub가 무엇인지, 번들된 두 도구를 한눈에, 기술 스택, 그리고 전체
   요청 흐름.
2. **[oeHosts와 oelink](02-oehosts-and-oelink.md)** — hosts 프로필 모델, 공개 범위와 공유, 프리셋,
   백업/복원, `oelink://` 프로토콜 핸들러.
3. **[oeProxy](03-oeproxy.md)** — 리버스 프록시, oeOID 요청 태깅, 실시간 트래픽 모니터, 포워드
   프록시.
4. **[배포 모드](04-deployment-modes.md)** — `standalone` 대 `workspace`, 워크스페이스와 역할 모델,
   가입과 승인, 두 모드 사이에서 달라지는 점.
5. **[종단간 암호화](05-end-to-end-encryption.md)** — `workspace` 모드에서 왜, 무엇이 암호화되는지, 키
   계층 구조, 비밀번호 복구, 워크스페이스키 회전, 공개 링크 공유.
6. **[보안 모델](06-security-model.md)** — 솔직한 위협 모델 요약: 암호화 설계가 무엇을 보호하고,
   명시적으로 무엇을 보호하지 않는지.

## 범위

이 문서들은 오늘 시점의 시스템을 있는 그대로 설명합니다. 로드맵이나 의사결정 기록이 아닙니다 —
문서에서 어떤 공백이나 아직 구현되지 않은 메커니즘을 언급한다면, 그것은 확정된 일정을 가진 계획이
아니라 현재 코드의 상태를 반영하는 것입니다.
